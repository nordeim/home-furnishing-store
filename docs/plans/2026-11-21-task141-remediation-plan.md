3. **The parent-directory .env trap (the cycle's environment lesson).** An env-less manual `next start` adopted `DATABASE_URL=file:/home/z/my-project/db/custom.db` from a sandbox-artifact `.env` at the workspace PARENT (no repo `.env` exists) — the poisoned server then served the static-catalogue fallback: `/api/products` 200 with real-looking seed data while `/api/health` honestly 500'd. 4. **`pkill -f "next start"` does not kill the server — the process is named `next-server`.** The wrapper (`npx next start`) dies to the pattern; the actual server survives, orphaned (PPID 1), still bound to :3100 — the NEXT start then dies on EADDRINUSE, and a mixed/truncated log (the dying process keeps its fd and writes at its old offset) makes the survivor look like the new one. The reliable kill: `pkill -f "next-server"` (or the PID from `ss -tlnp`). This cost one poisoned-taxonomy run (re-verified clean on the healthy server).
5. **The recycled-sandbox postmaster lies to pg_isready.** PostgreSQL processes survived the session recycle in name only: `pg_isready` answered "accepting connections" while every real query hung (the psql call had to be timeout-killed). The restart via the idempotent `setup_pg_z.sh` (data dir intact, no re-initdb) restored full function. Rule: after a sandbox recycle, verify with a REAL query (`SELECT 1` under a timeout), never a readiness probe.
6. **The first screenshot pair came out byte-identical.** 120 (home baseline) and 121 (the store-picker surface) captured the same page state — the picker is in view on both. Re-captured 121 with the picker focused (951 differing pixels — the focus ring), keeping each file's named intent honest.
